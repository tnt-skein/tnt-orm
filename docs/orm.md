# Модели в базе SQL

`tnt-orm` — шлюз моделей [`tnt-model`](https://github.com/tnt-skein/tnt-model)
для PostgreSQL и MySQL. Второй системы объявления здесь нет: модель
объявляется `model.define`, как и для спейса, — форма, проверка входа,
хуки, отметки времени, мягкое удаление, области, — а пакет даёт ей шлюз
`sql`. Запрос собирает [`tnt-sql`](https://github.com/tnt-skein/tnt-sql),
выполняет драйвер SQL ([`tnt-postgres`](https://github.com/tnt-skein/tnt-postgres),
[`tnt-mysql`](https://github.com/tnt-skein/tnt-mysql)), отказ базы
становится отказом модели того же рода.

```lua
local model = require('tnt.model')
local orm = require('tnt.orm')
local postgres = require('tnt.postgres')

local User = model.define({
    space = 'users',
    fields = {
        { 'id', 'unsigned', primary = true },
        { 'name', 'string', min = 1, max = 64, trim = true },
        { 'age', 'unsigned', max = 150 },
        { 'email', 'string', optional = true, max = 100 },
        model.created_at(),
        model.updated_at(),
    },
    indexes = { age = { parts = { 'age' }, unique = false } },
})

local db = postgres.new({ host = '127.0.0.1', port = 15432, user = 'app', password = secret, db = 'app' })
local binding = model.bind({ User }, model.settings({ source = 'sql' }), { sql = orm.gateway(db) })

binding.attach()
User.migration()(box)                                  -- create table if not exists "users" …
User.create({ id = 1, name = 'Мария', age = 46 })      -- insert into "users" …
User.where('age', '>=', 18):limit(50):all()            -- select … order by "age" asc, "id" asc limit 50
```

## Зачем пакет

Модель уже закрывает форму записи, проверку, миграцию, страницы
и фабрику для проверок, и её шлюзы знают, где данные в кластере
Tarantool. Не хватало одного — данных вне Tarantool. Писать для этого
вторую систему моделей значило бы описывать ту же форму дважды, и
описания разошлись бы молча. Пакет делает три вещи:

- **Та же модель поверх базы.** `find`, `create`, `save`, `delete`,
  `force_delete`, `restore`, `where…:all()/count()/first()`, `after`,
  `offset`, области, хуки и `model.atomic` работают на таблице так же,
  как на спейсе, и отказывают теми же родами `err.kind`. Код, который
  зовёт `User.find(7)`, не знает, где лежит запись.
- **Схема из объявления.** Шаг `Model.migration()` модели, привязанной
  к шлюзу `sql`, создаёт таблицу и индексы в базе вместо спейса. Шаг
  тот же, что и для спейса, поэтому шаги миграций приложения не меняются,
  когда меняется источник.
- **Источник выбирает настройка.** Раздел `models` привязки говорит
  `source = 'sql'`, и шлюз приходит тем же вызовом `model.bind`; код
  моделей и миграций остаётся прежним.

Зависит от [`tnt-model`](https://github.com/tnt-skein/tnt-model) (форма
записи, отказы, отметки), [`tnt-sql`](https://github.com/tnt-skein/tnt-sql)
(сборка запросов), [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(проверки аргументов), [`tnt-external`](https://github.com/tnt-skein/tnt-external)
и [`tnt-clock`](https://github.com/tnt-skein/tnt-clock) (часы отметок).
Драйвер приходит аргументом: какой из двух ставить, решает приложение,
и зависимостью пакета ни один из них не объявлен.

## Как пользоваться

### Шлюз

```lua
local gateway = orm.gateway(db)     -- db — драйвер tnt-postgres либо tnt-mysql
model.bind(models, model.settings({ source = 'sql' }), { sql = gateway })
```

`orm.gateway(db)` проверяет драйвер — таблица, `transaction`, диалект
`postgres` либо `mysql` — и отдаёт шлюз с `kind = 'sql'`. Иное — ошибка
программиста на строке вызывающего:

```lua
orm.gateway({ transaction = function() end, dialect = { name = 'tarantool' } })
--> исключение: диалект драйвера — одно из «postgres», «mysql», а не «tarantool»
```

Шлюз соединений не держит и `close` ничего не закрывает: драйвер
принадлежит приложению, и закрывает его тот, кто завёл.

### Источник настройкой

Источник выбирает раздел `models` настроек привязки (`model.settings`):
`source = 'sql'` — данные в базе. Раздел приложение берёт из своей
конфигурации, а шлюз приносит тем же вызовом `model.bind`, третьим
аргументом. Поэтому смена источника — правка настройки и того, что
уходит в `model.bind`, а код моделей и шагов миграций остаётся прежним:

```lua
local section = model.settings(config.models)                  -- { source = 'sql' }
local binding = model.bind(models, section, { sql = orm.gateway(db) })
```

- `source = 'sql'` — только явно: по ролям узла базу не угадать, и правило
  `auto` её не выберет.
- Без шлюза привязка — ошибка программиста: «источник sql: шлюза нет —
  его приносит тот, кто собирает привязку: model.bind(модели, раздел,
  { sql = orm.gateway(db) })».
- Функций `tnt_model_*` у такой привязки нет (`binding.functions` пуст):
  данных у узла нет, и отвечать ими за чужие нечем.
- `writes = 'forward'` с ним — ошибка программиста «пересылка записи:
  у источника sql данные в базе — запись и так уходит туда».

### Схема таблицы

```lua
schema.register(1, User.migration())      -- тот же шаг, что и для спейса
orm.statements(User, 'postgres')          -- текст, который шаг выполнит
```

`schema` — раннер шагов [`tnt-schema`](https://github.com/tnt-skein/tnt-schema);
шаг — обычная функция `function(box)`, и зовёт её любой раннер.

```sql
-- postgres
create table if not exists "users" ("id" bigint check ("id" >= 0) not null,
  "name" text collate "C" not null, "age" bigint check ("age" >= 0) not null,
  "email" text collate "C", "created_at" double precision,
  "updated_at" double precision, primary key ("id"))
create index if not exists "users_age" on "users" ("age")

-- mysql
create table if not exists `users` (`id` bigint unsigned not null,
  `name` varchar(64) character set utf8mb4 collate utf8mb4_0900_bin not null,
  `age` bigint unsigned not null,
  `email` varchar(100) character set utf8mb4 collate utf8mb4_0900_bin,
  `created_at` double, `updated_at` double, primary key (`id`), index `age` (`age`))
```

Имя индекса у PostgreSQL — `<таблица>_<индекс>`: имена индексов у него
общие на схему базы. Имя длиннее 63 байт сервер усекает, и шаг пишет его
уже усечённым; первичному ключу имя даёт сервер — `<таблица>_pkey`.
У MySQL имя индекса — имя из объявления, первичный зовётся `PRIMARY`.
По этим именам отказ о занятом значении узнаёт индекс модели (ниже,
«Отказы»).

Шаг решает по шлюзу модели в миг, когда идёт: модель, привязанная
к `sql`, получает таблицу, иначе — спейс. Правила те же, что у спейса:
**шаг создаёт таблицу по нынешнему объявлению**, а правки формы после
первого выпуска — отдельными шагами руками. Отказ базы срывает шаг, и
версия схемы вперёд не уходит.

| Род поля | PostgreSQL | MySQL |
|---|---|---|
| `unsigned` | `bigint check (… >= 0)` | `bigint unsigned` |
| `integer` | `bigint` | `bigint` |
| `number` | `double precision` | `double` |
| `string` | `text collate "C"` | `varchar(max)` до 16 383 знаков, иначе `longtext`; `utf8mb4_0900_bin` |
| `boolean` | `boolean` | `boolean` |
| `uuid` | `uuid` | `char(36)` |

Строка сравнивается побайтно и с учётом регистра, как в спейсе: иначе
уникальный индекс счёл бы «Мария» и «мария» одной записью, а сортировка
MySQL по умолчанию — ещё и «a» с «a ». Необязательное поле допускает
NULL, обязательное — `not null`. Длину, образец и перечень проверяет
модель, а не база.

### Страницы и порядок

Страница та же, что у спейса: порядок — части индекса, затем первичный
ключ; `<` и `<=` идут по убыванию; `after` — строго после записи;
`offset` — `offset` запроса. Пустое значение меньше любого, как NULL
в индексе TREE: оно идёт первым по возрастанию и подходит под `<`, `<=`
и `~=`, — а SQL пустое значение сравнением не видит, поэтому у
необязательного поля шлюз дописывает `or … is null` к таким условиям и
выражение `… is null` в порядок. У той же модели с индексом по `email`
(`email = { parts = { 'email' }, unique = true }`):

```lua
User.where('email', '<', 'n'):limit(20):all()
--> select … where ("email" < $1 or "email" is null)
--    order by "email" is null asc, "email" desc, "id" desc limit 20
User.where('age', '>=', 18):after({ age = 30, id = 5 }):all()
--> select … where "age" >= $1::int8 and "age" >= $2::int8
--    and (("age" > $3::int8) or ("age" = $4::int8 and "id" > $5::int8))
--    order by "age" asc, "id" asc limit 100
```

Страница, кончившаяся записью без почты, продолжается от её места:
пустая часть курсора — место NULL, как в индексе (документ
[`tnt-model`](https://github.com/tnt-skein/tnt-model), «Выборка»).
Сравнение с пустым параметром SQL не видит — `"email" < null` не истинно
никогда, — и шлюз пишет его проверкой на пустоту: равно пустому и
не больше его — `is null`, больше — `is not null`, не меньше — любое
значение, и условия нет. Строго меньше пустого нет ничего, и по убыванию
такой ветки в запросе нет:

```lua
User.where('email', '<', 'n'):limit(20):after({ id = 4 }):all()   -- после записи 4 без почты
--> select … where ("email" < $1 or "email" is null) and "email" is null
--    and (("email" is null and "id" < $2::int8))
--    order by "email" is null asc, "email" desc, "id" desc limit 20
```

Условия областей и мягкого удаления база выполняет сама: страница,
смещение и `after` считают только подошедшие записи, и обхода кусками,
как у спейса, здесь нет.

### Значения

Целое у PostgreSQL уходит с приведением `$1::int8` — его ставит
кодирование значений [`tnt-storage`](https://github.com/tnt-skein/tnt-storage),
которым `tnt-sql` собирает запрос: число Lua рок шлёт типом `numeric`,
и сравнение столбца `bigint` с `numeric` шло бы мимо индекса. `uuid`
уходит cdata с `$1::uuid`, пустое значение — с приведением к типу
столбца (`$1::boolean`): NULL-параметр рок шлёт типом `text`, и столбец
другого типа его не принимает. Обратно `double precision` PostgreSQL
приходит строкой, `boolean` MySQL — числом, и шлюз приводит их к роду
поля. Целое за 2^53 проходит в обе стороны cdata без потери цифр —
ключи 2^53 и 2^53 + 1 сверены на обоих серверах.

### Отметки, хуки, мягкое удаление

Отметки времени и признак мягкого удаления ставит шлюз — как шлюз
`local` у спейса. Вставка — один оператор. Замена, удаление
и восстановление читают прежнюю строку `select … for update` и пишут
на том же соединении в одной транзакции: отметка создания переходит
от прежней строки, и чужая запись между чтением и записью её
не перетрёт. Хуки идут у модели, как и прежде.

### Транзакции

`model.atomic(fn, …)` — транзакция драйвера на одном соединении: пока
идёт тело, действия модели в том же файбере идут её соединением.

```lua
model.atomic(function()
    assert(User.create({ id = 1, name = 'a', age = 20 }))
    assert(User.create({ id = 2, name = 'b', age = 21 }))

    return 'готово'
end)
--> 'готово'
```

- Как у `box.atomic`: исключение тела откатывает транзакцию и идёт
  дальше, иначе — фиксация и ответ тела как есть, даже `nil, err`.
- **Фиксация бывает отказом** — сеть, сериализация, — и тогда ответ —
  пара `nil, err` с родом модели.
- **Отказ оператора помечает транзакцию**: `create` на занятый ключ
  отдаёт `conflict`, следующие операторы тела получают тот же отказ,
  и фиксации не будет — ответ `nil, err`. `err` — тот же отказ модели,
  что получил отказанный оператор: с его таблицей и именем занятого
  индекса, а не «в транзакции». Так зовётся лишь отказ самой фиксации,
  которого не видел ни один оператор. У спейса отказанная запись
  транзакцию не портит.
- Вложенный `model.atomic` — ошибка программиста; файбер, порождённый
  телом, идёт мимо транзакции — пулом драйвера.
- Внутри транзакции box шлюз транзакции не открывает — это исключение
  драйвера: ожидание сети оборвало бы транзакцию memtx.

### Отказы

| Что сказала база | `err.kind` |
|---|---|
| занятое значение уникального индекса (`23505`, `1062`) | `conflict` — текст называет индекс: «запись users с таким email уже есть», первичный — ключом: «запись users с таким ключом уже есть» |
| база только для чтения (`25006`, `1290`, `1792`) | `readonly` |
| значение не по столбцу: класс `22` PostgreSQL, `23502`, `23514`, `1048`, `1264`, `1366`, `1406`, `3819`; значение, которое не ушло вовсе (строка с нулевым байтом у PostgreSQL) | `invalid` с `fields['$']` — первая строка отказа |
| всё прочее: сеть, срок, пул, закрытый драйвер, конфликт сериализации, таблицы нет | `unavailable` |

Текст `conflict` называет индекс, который занят: ключ свободен,
а занята почта — и «с таким ключом» послало бы искать не то. Имя
индекса драйвер отдельным полем не отдаёт, и шлюз берёт его из текста
отказа: PostgreSQL зовёт ограничение в первой строке — `"users_email"`,
MySQL — последним в кавычках, `'users.email'` (до 8.0.19 — `'email'`).
Имя сверяется с тем, что дал индексу шаг схемы (выше, «Схема таблицы»),
поэтому значение строки, где бывает что угодно, индекс не подменит.
У той же модели с индексом по `email`:

```lua
User.create({ id = 1, name = 'Мария', age = 46, email = 'm@x' })
User.create({ id = 2, name = 'Иван', age = 30, email = 'm@x' })
--> nil, 'запись users с таким email уже есть'
User.create({ id = 1, name = 'Иван', age = 30 })
--> nil, 'запись users с таким ключом уже есть'
```

Индекс, которого модель не знает (его завели в базе мимо объявления),
и отказ `23505`, поднятый триггером без имени индекса, текст не
называет: «запись users с таким значением уникального индекса уже есть».
Ключом такое не назвать — занят мог быть любой уникальный индекс.

Отказ драйвера остаётся в поле `err.cause` — тому, кому нужны
`server_code` и `retriable`:

```lua
local _, err = User.find(1)          -- таблицы нет
err.kind                             --> 'unavailable'
tostring(err)                        --> 'база не выполнила запрос (users): ERROR:  relation "users" does not exist …'
err.cause.server_code                --> '42P01'
```

## Чем SQL-шлюз отличается от спейсов

- **Транзакция** — транзакция драйвера на одном соединении, а не
  `box.atomic`: фиксация бывает отказом, а отказ оператора помечает
  транзакцию целиком. Вложенной нет.
- **Типы** — у столбцов свои. Беззнаковое у PostgreSQL — `bigint`,
  его предел 2^63 − 1, а не 2^64 − 1: больше — `invalid`. Строка MySQL
  с индексом обязана иметь `max`: `longtext` в индекс не входит, и шаг
  схемы сорвётся отказом сервера.
- **Страницы** — порядок и `after` те же, но индекс по необязательному
  полю страницу сортирует, а не читает по порядку: пустое значение
  ставит первым выражение `… is null`, а не сам индекс. Условия областей
  выполняет база — обхода кусками нет, и предела среза файбера тоже.
- **Замена — две операции под замком**: `select … for update`, затем
  правка либо вставка, в одной транзакции. Замена нового ключа
  одновременно с чужой вставкой того же ключа — `conflict`, у спейса
  замена не отказывает никогда. У MySQL замок на отсутствующую строку
  берёт замок промежутка, и встречные вставки под нагрузкой бывают
  взаимоблокировкой — `unavailable`.
- **Версия схемы — на узле, таблица — в общей базе.** Шаг `tnt-schema`
  идёт на каждом узле, который разделяет базу, поэтому каждый оператор
  схемы переживает повтор (`if not exists`). Шаг, в котором SQL идёт
  после изменения спейса, срывается: ожидание сети обрывает транзакцию
  с DDL box; SQL — первым либо отдельным шагом.
- **Нет топологии.** Функций `tnt_model_*`, веера и пересылки у
  источника `sql` нет: все узлы ходят в одну базу напрямую, и чтение
  с реплики базы — дело драйвера и его адреса.

## Чем пришлось поступиться

- **Порядок по необязательному полю — сортировка на сервере.** Пустое
  значение первым ставит выражение, и индекс по такому полю отбирает
  строки, но не упорядочивает их.
- **Замена стоит транзакции из двух операторов**, а не одного
  `replace`: отметку создания иначе не взять у прежней строки, а
  `on duplicate key update` MySQL при втором уникальном индексе правит
  чужую строку.
- **Имя занятого индекса — из текста отказа базы.** Драйвер отдаёт
  код сервера, но не имя ограничения, и шлюз находит имя в тексте.
  Индекс, заведённый мимо объявления, и отказ триггера без имени идут
  без имени индекса.
- **Отказ оператора в транзакции — отказ всей транзакции**, как у
  PostgreSQL; у MySQL транзакция после ошибки цела, но договор драйвера
  один на оба сервера.
- **Схема только создаётся.** Изменить колонку, добавить индекс
  к существующей таблице — отдельный шаг руками, как и у спейса.
- **Строка MySQL без `max` — `longtext`**, и в индекс она не входит.
- **Беззнаковое у PostgreSQL до 2^63 − 1.**

## Проверки

Проверки лежат в `test/` и идут на luatest; зовутся они через `make`,
который держит каталог узлов luatest своим.

```sh
make deps     # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check    # форматирование, линт, проверки, покрытие с порогом 100 %
```

- `gateway_test.lua`, `query_test.lua`, `ddl_test.lua`, `orm_test.lua` —
  53 проверки на двойнике драйвера (`test/helper.lua`): тексты
  и параметры запросов дословно на обоих диалектах, замок строки
